# Changelog

One line per release, newest first, from the release commits. Versions before 0.1.10 and
versions without a release commit of their own are folded into the next listed one.

- **0.1.117** (2026-11-27): `/foundry setup` (and `foundry setup` in a terminal) first does what install.sh sets up besides the plugin itself: the state, foreman and worktree directories, config.json (mode 600), the foreman directory's trust entry, preflight and the `~/.local/bin/foundry` shim, idempotently; then the Nerd Font steps as before. A session on a machine with no config.json yet starts with the one line `foundry is not set up: run /foundry setup`; no hook sets anything up. The README's marketplace path is add, install, `/foundry setup`.
- **0.1.116** (2026-11-27): inline review comments through `gh api`, approved by the owner: the Bash guard lets a POST to `pulls/<n>/comments` through, and a POST to `pulls/<n>/reviews` whose event (`-f`/`-F event=`, or `"event"` in the `--input` JSON) is COMMENT or REQUEST_CHANGES. A review POST with APPROVE, or with no or an unreadable event, still goes through `gh pr review --approve` and its gate; merges and ref writes stay refused.
- **0.1.115** (2026-11-27): one board state per unit (`board.unit_state`): the group a row sits in and its state cell on the chat board, the side pane and board.html come from it. A finished unit with an open PR is 팀 대기, one with a merged PR no release tag holds yet (in a repo with a release step) is 머지됨·릴리스 대기, a done release unit or a released PR is 릴리스 완료, cancelled is 취소; a merged PR in a `release.none` repo no longer waits on a release, and a closed cell shows no wait, plan flag or deadline. Fixed groups in one order with counts and ko/ja/en labels: 진행 중 / 오너 대기 / 팀 대기 / 대기열 / 머지됨·릴리스 대기 / 릴리스 완료 / 완료 / 취소. `foundry board archive --older <N>d|--all-done [--dry-run]` records 릴리스 완료/완료/취소 units into the archive view (`foundry board --archived`) and deletes nothing; prefs `board.archive_days` (7) moves them there by age; the foreman and the foundry-status skill map 「완료된 거 정리해줘」 to it.
- **0.1.114** (2026-11-27): the Marp decks in docs/slides are removed. A `decision:<key>` ref resolves when the owner answered that `decision ask` (a unit's or a top-level one), not only a card, and answering an ask resolves what it unblocked. The public marketplace is named `foundry` (`claude plugin install foundry@foundry`); install.sh and uninstall.sh read the marketplace name from the layout they run in (`local-foundry` in the private root). Files under a top-level `.foundry-*/` directory of a worktree count as a lead's memos, so a finished worktree with one is removed with a backup instead of refused.
- **0.1.113** (2026-11-26): Argo locks and merge state. The merge hook names the lock it took and how to release it; `foundry lock release` of a name the unit does not hold lists the locks it does hold with their exact commands; `foundry lock list` and the owner's `/foundry lock`; a prod `foundry unit deployed` releases the unit's argo locks (by deploy-done), and an argo lock held over 60 minutes by a parked or waiting unit is a board mismatch. mergeStateStatus UNKNOWN is re-read five times (2/4/8/8/8 s, PreToolUse hook timeout now 60 s) before the refusal, which points to the new `mergeable` wait kind (cleared by the watcher once GitHub settles); a ci wait on checks that already finished is refused
- **0.1.112** (2026-11-26): a batch release that cuts one tag per app at the same commit records the other app tags with `foundry release tag <unit> --tag ...` (owner or the unit's own lead); each tag must exist in the release's repo at the commit of a tag the unit already recorded, and the check fails closed when GitHub cannot be read. The deploy PR approve accepts any recorded tag (and `<tag>-<image>`); an unrecorded tag with the same suffix is still refused
- **0.1.111** (2026-11-25): docs/concepts.md draws its eight diagrams as standalone SVG files in docs/img (hierarchy, components, sequence, approval tiers, sweeper, Monitor and cron flow, dependency graph, day timeline), each with its own style and arrow markers, a solid background and light and dark colors, in English with example data; the denylist scans `.svg`. The suite runs with a throwaway HOME, state dir and Claude config for the whole process (the user's ui.language no longer leaks into it) and fails when the real shim or prefs change; the shim refuses to bake a test config into a home outside the test scratch
